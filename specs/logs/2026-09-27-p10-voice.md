# 2026-09-27 — P10 voice

## What shipped
F5.1/F5.2 (voice intake) and F5.3 (read-aloud), via a real, working, key-free `LanguageService` backed by the browser's own Web Speech API: mic buttons on the profile form's `fullName`, `age`, `estimatedCost`, `annualFamilyIncome` and district search, and read-aloud buttons on the recommender's scheme cards and scheme detail screen, composing a spoken summary from already-localized on-screen text (scheme name, top reason, approval odds).

## What was already there / already done elsewhere
F5.4 (icon-led UI) and F5.5 (assisted mode) were already substantially shipped in P3 — this phase only needed F5.1/F5.2/F5.3. No Bhashini/Groq keys, SDK, or backend exist anywhere in the repo (confirmed by investigation before writing the spec); `docs/BUILD-PROMPT.md` explicitly allows stub-quality voice for the hackathon, but Web Speech API gave a genuinely working alternative for free.

## Design decisions (confirmed with the user before writing the spec)
1. Web Speech API (`SpeechRecognition` + `window.speechSynthesis`), not a fake stub — wrapped behind a `LanguageService` interface so a real Bhashini backend can later replace only the implementation.
2. Scope: profile form intake + recommender results read-aloud only, no new screens.
3. Graceful degradation is mandatory — `isSttSupported()`/`isTtsSupported()` gate both UI pieces; they hide, not error, when the browser lacks support.
4. STT/TTS language follows the app's current i18n language (`hi-IN`/`en-IN`) — a disclosed limitation, since Web Speech API's Hindi support varies by browser/OS.
5. `LanguageService` was added directly to the existing `Container`/`RepositoryProvider` DI pattern rather than a parallel context, matching existing conventions exactly.

## New pieces
`core/services/{languageService.ts,webSpeechLanguageService.ts}` (interface + browser implementation), `types/speech-recognition.d.ts` (ambient declarations — `SpeechRecognition` isn't in `lib.dom.d.ts`, `SpeechSynthesis` already is), `shared/components/{MicButton,ReadAloudButton}.tsx`, a `MockLanguageService` test double wired into `renderApp` the same way mock repositories already are.
